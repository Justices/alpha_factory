## 平台操作分页/限流约定（老刘强调）

**核心原则：涉及平台(WorldQuant BRAIN)的操作，必须分页 + 循环拉取 + 节流，否则触发 429。**

平台操作盘点：
- `fetch_datafields`(alpha_machine)：分页(offset) + 节流(page_delay 0.5s) + **429 退避重试(新增)** ← 本次修复
- `fetch_user_alphas`(alpha_source)：分页(page+offset) + page_size + max_pages 防无限循环 ✅
- `datafield_ingest`(platform)：增量采集(每次1字段) + 串行节流 ✅
- `simulate`(alpha_machine)：批次提交 + 轮询(poll_interval 5s) + Retry-After 处理 ✅

本次修复：`alpha_machine.fetch_datafields` 加 `max_retries` 参数 + `_retry_after_seconds` 辅助（读 Retry-After 头，支持秒值/HTTP-date，解析失败兜底 1.5s），429 时退避重试当前页（offset 不变）。

注意：`fetch_datafields` 已有完整限流防护——分页(limit=50) + 顺序同步翻页 + 页间 page_delay 0.5s 节流 + 429 退避重试(max_retries=5, 读 Retry-After, offset 不变重试当前页)。429 哪怕偶发也会被退避吸收，**不是阻断性障碍**，最终能拉到全量字段。本地缓存 `data/fields/*` 优先（`cache/datafields.aget_datafields`）的价值是**速度**（避免每次翻 30+ 页走网络），而非 429 兜底。（老刘 20:52 指正：分页大小控制 + 顺序同步执行已到位，不应再把 429 当障碍）
