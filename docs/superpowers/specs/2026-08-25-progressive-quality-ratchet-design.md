# Alpha Factory 渐进式质量棘轮设计

## 目标

让 CI 对全部 178 个 Python 文件可见，同时不为本轮擅自重写历史代码。现有债务被记录为基线；任何新增 Ruff、Mypy、覆盖率或死代码退化都使 CI 失败。

## 现状

当前 Ruff/Mypy 严格门禁只覆盖 26 个本轮改动文件；全库隔离 Ruff 检查有 368 项历史问题，Mypy 全包检查会触发内部序列化错误。测试共 350 项通过，但没有覆盖率阈值，也未安装死代码检测器。

## 设计

保留现有 26 文件的零错误严格门禁，并新增 `tools/quality_ratchet.py` 作为全库棘轮入口。脚本以结构化输出运行 Ruff、Mypy、coverage 和 Vulture，把问题规范化为稳定指纹，与版本控制中的 `quality-baseline.json` 比较；旧指纹允许存在，新指纹或指标倒退返回非零。工具崩溃单独记为失败，不伪装为零问题。

Mypy 先按包分片运行，绕过一次性全包序列化崩溃，并把每片错误指纹合并。覆盖率基线以本次实测值为起点，允许同一次变更提升但不允许下降；同时设最低绝对阈值，初始值取向下取整后的当前覆盖率。Vulture 使用 80% confidence，兼容门面、插件入口和声明式路由通过显式白名单保留。

CI 顺序为：compileall、严格 Ruff、严格 Mypy、全量 pytest+coverage、全库质量棘轮。提供 `baseline --update` 显式更新命令，但 CI 永不自动更新基线。

## 验收

- 所有 Python 文件均进入至少一种全库扫描，新增问题能由回归测试证明会失败。
- 现有严格范围继续保持 Ruff/Mypy 零错误。
- 覆盖率与死代码工具使用固定版本，结果可在 Windows 与 CI 重现。
- 基线文件只保存计数、指纹和阈值，不保存大段原始日志。
- 全量测试与质量工作流通过。
